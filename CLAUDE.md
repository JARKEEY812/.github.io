# Проект: SEO-сайты

## Главное правило — точность
- Ни одного утверждения о SEO (лимиты, правила Google/Яндекса, синтаксис schema.org) без проверки по первоисточнику: developers.google.com/search, yandex.ru/support/webmaster, schema.org, web.dev. Источник — ссылкой в ответе.
- Не уверен — пиши «не проверено» и делегируй `seo-researcher`. Не угадывай.
- Перед правкой страницы: `python3 .claude/skills/seo-verify/check.py <файл или папка>` — до и после. Изменение, которое добавляет ошибки, не коммитить.
- Никогда не трогать без явного запроса: robots.txt `Disallow`, `noindex`, canonical, редиректы, URL-структуру. Это действия с риском потери трафика — сначала спросить.

## Экономия токенов
- Отвечать коротко: результат, затем список изменений. Без пересказа кода и пояснений «что я сейчас сделаю».
- Читать файлы частями (Grep → Read с offset/limit), а не целиком.
- Механические проверки — скриптом `check.py`, а не чтением HTML глазами.
- Одна задача — одна сессия. Новая тема → `/clear`.

## Агенты (изолированные)
Каждый агент получает самодостаточное задание и возвращает короткий итог. Агенты не вызывают друг друга и не передают задачу дальше — координирует только основная сессия.

| Агент | Модель | Что делает | Права |
|---|---|---|---|
| `seo-researcher` | opus | Ищет и сверяет факты с первоисточниками | только чтение + веб |
| `seo-auditor` | haiku | Аудит кода сайта по чек-листу | только чтение |
| `seo-fixer` | haiku | Вносит одну конкретную правку | правка файлов |
| `seo-verifier` | opus | Проверяет готовый diff на ошибки и регрессии | только чтение |

Порядок: researcher/auditor (параллельно, если задачи независимы) → fixer → verifier. Каждому — только нужные ему данные, не вся история.
